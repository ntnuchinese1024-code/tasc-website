# 正式上線與網域設定

把官網從 `tasc-preview.netlify.app` 搬到 **`tasctaiwan.tw`**，
並把報名系統的確認信設定完成。

照著順序做。DNS 那幾步做完要等，其他步驟大約 30 分鐘。

---

## 先看懂：這次動到的三個東西

| 東西 | 現在在哪 | 這次要做什麼 |
|---|---|---|
| 官網（介紹、課程、報導） | Netlify，`tasc-preview.netlify.app` | 接上 `tasctaiwan.tw`，並開放 Google 收錄 |
| 報名系統（表單、後台） | Vercel，`tasc-registration.vercel.app` | **網址不動**，只設定寄信 |
| 確認信 | 目前沒設定，信寄不出去 | 用 Resend 從 `no-reply@tasctaiwan.tw` 寄出 |

「網域」和「寄信」其實是同一件事的兩面：你在網域的 DNS 設定裡加幾筆記錄，
一種指向網站主機，另一種證明「這個網域授權 Resend 幫它寄信」。
所以兩邊都要進同一個 DNS 畫面，建議一次做完。

---

## 第零步：確認網域真的可以用了

**這一步沒過的話，後面全部會失敗**，而且失敗訊息長得像設定錯誤，很容易白忙。

在終端機執行：

```bash
dig @8.8.8.8 +short NS tasctaiwan.tw
```

- **有印出幾行網址**（像 `ns1.某某.com`）→ 網域活了，繼續往下做。
- **完全沒有東西** → 網域還沒生效。剛買的 `.tw` 網域要等註冊機構（TWNIC）公布，
  通常幾小時內，最久隔天。先去泡茶，過幾小時再跑一次這行指令。

> 2026-08-21 下午檢查時是「沒有東西」的狀態，所以你多半得等一下。

## 第一步：官網接上網域

### 1-1 在 Netlify 加網域

1. 開 <https://app.netlify.com>，進到 `tasc-preview` 這個站。
2. 上方 **Domain management**（或 Site configuration → Domains）。
3. **Add a domain** → 輸入 `www.tasctaiwan.tw` → Verify → Add。
4. 再 **Add a domain** 一次 → 輸入 `tasctaiwan.tw`（不含 www）→ Add。
5. Netlify 會問要不要用它的 DNS（Netlify DNS）。**選「Use external DNS」/「Add DNS records manually」**。

> **為什麼不用 Netlify DNS？** 用了的話，網域的控制權就寄放在 Netlify。
> 這個專案從一開始的原則就是「不綁任何平台，隨時可以搬」，
> DNS 留在你買網域的地方，將來要換主機只要改兩筆記錄，不用搬整個網域。

6. 確認 **`tasctaiwan.tw`（不含 www）旁邊有 ★ Primary domain**。
   `www.tasctaiwan.tw` 會自動變成 “Redirects automatically to primary domain”，
   舊的 `tasc-preview.netlify.app` 也會一起轉過來，
   不會出現「同一個網站有三個網址」的狀況。

> **Primary domain 必須和 `astro.config.mjs` 裡的 `site` 一致。**
> 現在兩邊都是不含 www 的 `https://tasctaiwan.tw`。
> 哪天改了其中一邊，另一邊一定要跟著改，否則每一頁的 canonical 會指到
> 一個會 301 轉走的網址，Google 會看得很困惑。

> **清掉重複的那一筆**：Netlify 上目前有兩筆 `www.tasctaiwan.tw`——
> 一筆是自動產生的 redirect，一筆是你手動加的 “Domain alias”。
> 把 **Domain alias 那一筆** 用 Options → Remove 刪掉，留自動產生的那筆就好。
> 留著不會壞事，只是憑證會多申請一份、清單看起來混亂。

### 1-2 在註冊商加兩筆 DNS 記錄

網域是在 **Gandi** 買的。登入 <https://admin.gandi.net> → 左邊 **Domain** →
點 `tasctaiwan.tw` → 左邊選單 **DNS Records**。

**重點：這兩筆記錄已經存在了，你要「改」不是「新增」。**
Gandi 買網域時會自動塞一組指向它自己招牌頁的記錄，現在畫面上應該長這樣：

| 類型 | 名稱 | 目前的值（Gandi 預設） |
|---|---|---|
| `A` | `@` | `217.70.184.38` |
| `CNAME` | `www` | `webredir.vip.gandi.net.` |

把它們**各自按鉛筆（Edit）圖示改成**：

| 類型 | 名稱 | 改成 | 說明 |
|---|---|---|---|
| `A` | `@` | `75.2.60.5` | 不含 www 的版本指向 Netlify |
| `CNAME` | `www` | `tasc-preview.netlify.app.` | www 版指向 Netlify |

幾個 Gandi 的眉角：

- **不要用「新增」再加一筆同名的**。同一個名稱有兩筆會打架，
  網站會時好時壞、而且極難查。一定是編輯既有那筆。
- **CNAME 的值結尾要有一個句點**：`tasc-preview.netlify.app.`
  Gandi 用的是標準區域檔格式，少了句點它會理解成
  `tasc-preview.netlify.app.tasctaiwan.tw`，就錯了。
- **名稱欄位只填 `www`**，不要填 `www.tasctaiwan.tw`，同樣會變成疊字。
- **TTL** 保持預設（Gandi 最低 300 秒）即可。
- Gandi 右上角有個 **“Edit the zone file”**（純文字模式）。
  熟悉的話用它一次改完比較快，但一個字打錯整份就壞掉，建議還是用鉛筆逐筆改。

> 改完 www 那筆之後，Gandi 的「網頁轉址」（Web Forwarding）功能就不再作用了，
> 這是正常的——那本來就是它預設的招牌頁，我們不需要。

### 1-3 等待與確認

DNS 生效通常 10–30 分鐘。確認指令：

```bash
dig @8.8.8.8 +short tasctaiwan.tw
dig @8.8.8.8 +short www.tasctaiwan.tw
```

第一行要印出 `75.2.60.5`，第二行要印出 netlify 相關的位址。
還印著 `217.70.184.38` 或 `webredir.vip.gandi.net.` 就是還沒生效，再等一下。接著回 Netlify 的 Domain management，
確認兩個網域旁邊都出現綠色的 **HTTPS / Netlify certificate is provisioned**。
憑證是 Netlify 自動申請的，不用你動手，但要 DNS 先通它才申請得到。

> 如果卡在 “awaiting external DNS”，多半是 1-2 的名稱欄位填錯。回去看有沒有變成疊字。

**這一步做完，`https://tasctaiwan.tw` 就打得開了**，但頁面上還會有預覽提示條，
而且還沒開放 Google 收錄。下一步處理。

## 第二步：正式開放（拿掉預覽狀態）

確定網域打得開、內容也都對之後，才做這一步。

在終端機執行：

```bash
cd /Users/dr.lin/Desktop/tasc-website && sed -i '' 's/export const IS_PREVIEW = true;/export const IS_PREVIEW = false;/' src/lib/site.ts && git add src/lib/site.ts && git commit -m "正式對外公開" && git push
```

這一行做了四件事：把預覽開關關掉、記錄這次改動、推上 GitHub。
Netlify 收到之後會自己重新建置，約 1–2 分鐘後生效。同時會發生：

1. 網頁上方那條「這是預覽版」的提示條消失
2. `robots.txt` 從「請不要收錄」變成「歡迎收錄」
3. 每頁的 `noindex` 標籤消失

> **順序很重要**：先確認網域通了再關預覽。反過來的話，
> Google 會先收錄到 `tasc-preview.netlify.app`，之後要花時間才能導正。

確認方式：

```bash
curl -s https://tasctaiwan.tw/robots.txt
```

印出 `Allow: /` 就成功了。

## 第三步：設定確認信（Resend）

報名系統目前**沒有**寄信能力——學員報名會成功、資料會進資料庫，但收不到確認信。
這一步補上。

### 3-1 註冊並驗證網域

1. 開 <https://resend.com>，用學會帳號（`tasc.tw@gmail.com`）註冊。
2. 左邊 **Domains** → **Add Domain** → 填 `tasctaiwan.tw`（**不要**填 www）。
3. Region 選 **Tokyo (ap-northeast-1)**，離台灣最近。
4. Resend 會列出三筆 DNS 記錄要你去加。**每個帳號的值都不一樣，一定要照它畫面上的複製**，
   長相大致是：

   | 類型 | 名稱 | 用途 |
   |---|---|---|
   | `MX` | `send` | 處理退信 |
   | `TXT` | `send` | SPF，宣告誰可以代表這個網域寄信 |
   | `TXT` | `resend._domainkey` | DKIM，一長串金鑰，幫每封信簽章 |

5. 到註冊商的同一個 DNS 畫面把三筆加進去，回 Resend 按 **Verify**。通常 10 分鐘內轉成綠色 Verified。

> **會不會影響學會現在的 Gmail？** 不會。這些記錄都掛在 `send.tasctaiwan.tw`
> 這個子名稱底下，不是網域本身，收信完全不受影響。
> 你之後仍然可以另外設定 `@tasctaiwan.tw` 的正式信箱。

### 3-2 順便加一筆 DMARC（建議）

再加一筆 TXT，讓信比較不會進垃圾桶：

| 類型 | 名稱 | 值 |
|---|---|---|
| `TXT` | `_dmarc` | `v=DMARC1; p=none; rua=mailto:tasc.tw@gmail.com` |

`p=none` 是「只觀察、不擋信」，最安全的起手式。

### 3-3 拿 API 金鑰

Resend 左邊 **API Keys** → **Create API Key**：

- Name：`tasc-registration`
- Permission：**Sending access**（不要給 Full access）
- Domain：限定 `tasctaiwan.tw`

**這串 key 只會顯示一次**，複製起來，直接貼到下一步。
不要存進這台電腦的任何檔案，也不要貼進聊天視窗。

## 第四步：把設定填進 Vercel

金鑰不是寫在程式碼裡，是填在 Vercel 的設定畫面——這樣金鑰不會進版控，換人也不用改程式。

1. 開 <https://vercel.com>，進 `tasc-registration` 專案。
2. **Settings → Environment Variables**。
3. 加這幾組（Environment 三個都勾：Production / Preview / Development）：

   | Name | Value |
   |---|---|
   | `RESEND_API_KEY` | 第 3-3 步那串金鑰 |
   | `RESEND_FROM_EMAIL` | `社團法人台灣性諮商學會 <no-reply@tasctaiwan.tw>` |
   | `RESEND_REPLY_TO` | `tasc.tw@gmail.com`（學員按回覆會寄到這） |
   | `RESEND_ARCHIVE_BCC` | `tasc.tw@gmail.com`（每封信留一份副本，選填） |

4. 順便檢查已經有的兩組：
   - `NEXT_PUBLIC_SUPABASE_URL` 必須是**乾淨的**專案網址 `https://xxxx.supabase.co`，
     **結尾不可以有 `/rest/v1`**。（這個坑踩過一次，症狀是首頁沒活動＋後台登不進去。）
   - `SITE_DEPLOY_HOOK_URL` 必須是 **Cloudflare** 的 Deploy Hook 網址
     （開頭是 `https://api.cloudflare.com/client/v4/workers/builds/deploy_hooks/`）。
     取得方式：Cloudflare → Workers & Pages → `tasctaiwan` → Settings → Builds → Deploy Hooks。
     **不要用 Netlify 的舊網址**——官網 2026-08-21 已從 Netlify 搬到 Cloudflare，
     舊網址還會回 HTTP 200，但打的是一個沒人看的廢站，
     症狀是「後台按了立即更新官網，正式站卻毫無動靜」。

     這串網址等於重建官網的遙控器，拿到的人可以無限觸發建置，
     所以只放在 Vercel 環境變數與 GitHub secret 裡，不要寫進任何檔案或文件。

5. **改完環境變數一定要重新部署才會生效**：
   **Deployments** → 最上面那筆右邊 `⋯` → **Redeploy**。

> 不重新部署的話，你會以為設定沒作用而一直重試。這是最常見的卡關點。

## 第五步：實際寄一封測試信

設定不能只用看的，一定要真的跑一次。

1. 用手機（不要用平常登入後台的瀏覽器）開一場正在開放報名的課程頁。
2. 用你自己的私人信箱報名一筆，隨便填。
3. 檢查：
   - [ ] 信箱收到「報名成功，待對帳」的通知信
   - [ ] 寄件者顯示 `社團法人台灣性諮商學會`，位址是 `no-reply@tasctaiwan.tw`
   - [ ] 信裡的金額對應你選的身分別（會員／非會員價不一樣，這裡最容易出錯）
   - [ ] 信**沒有**進垃圾郵件匣
   - [ ] 按「回覆」時收件者自動變成秘書處信箱
4. 進後台 `tasc-registration.vercel.app/admin` → 報名管理，把那筆改成**已確認**。
   應該會再收到一封「已完成報名」的信。
5. 測完把這筆測試報名**取消**，名額才會還回去。

> 信沒收到的話，去 Resend 左邊的 **Emails** 看紀錄：
> 有紀錄但 bounced＝收件位址問題；完全沒紀錄＝`RESEND_API_KEY` 沒生效，
> 多半是第四步沒有 Redeploy。

## 出事的時候

| 症狀 | 多半是 |
|---|---|
| 網域打不開，瀏覽器說找不到伺服器 | DNS 還沒生效，或名稱欄位填成疊字 |
| 打得開但顯示 Netlify 的 404 | Netlify 那邊沒把網域加進這個站 |
| 顯示「連線不安全」 | 憑證還在申請中，等 10 分鐘；超過一小時就回 Netlify 按 Renew certificate |
| 官網課程消失 | 報名系統的 API 掛了。開 `tasc-registration.vercel.app/api/events?scope=open` 看有沒有回東西 |
| 名額數字停在舊值 | `ALLOWED_ORIGINS` 填了但漏了新網址，或結尾多了斜線 |
| 確認信沒寄出 | Resend 網域沒驗證通過，或第四步改完沒 Redeploy |
| Netlify 建置失敗說 unrecognized Git contributor | commit 訊息裡混進了 `Co-Authored-By`。這個 repo 一律不要加 |
