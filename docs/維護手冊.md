# 台灣性諮商學會網站 維護手冊

這份手冊是寫給「不一定懂寫程式，但需要負責網站內容」的人看的——不管你是現任或未來的理事長、秘書處、幹部，或是被指派來維護網站的夥伴。

目標只有一個：**就算完全沒碰過這個網站，照著這份手冊，也能自己改內容、自己上線，或是找 AI（例如 Claude）幫你做。**

---

## 這個網站是怎麼運作的（白話版）

不懂技術也沒關係，先建立這個大概念就好：

1. 網站的內容（文字、活動公告等）都寫在一個個「文字檔案」裡，不是存在某個你要登入的後台系統。
2. 這些檔案存放在一個叫做 **Git 倉庫（repository）** 的資料夾裡，你可以把它想成「有自動記錄每一次修改歷史的資料夾」——誰、什麼時候、改了什麼，都查得到，改壞了也能退回去。
3. 想要「發布」網站更新時，把改好的檔案「打包」成純網頁檔案，丟到網路空間上，網站就更新了。

這代表：就算未來換人負責、換掉某個工具或某個網路平台，內容本身永遠都在，不會被鎖在某一家公司的系統裡打不開。這也是這次特地不選 Wix/Weebly 這類「一站式」平台的原因。

---

## 情境一：我只是要改文字／新增一則活動公告

（本節待網站頁面架構定案後補上實際操作步驟與範例檔案路徑）

大方向會是：
1. 找到對應的內容檔案（例如「課程公告」對應的檔案）。
2. 複製一份現有的活動格式，改成新的日期、標題、內容。
3. 存檔。
4. 依「情境三：怎麼發布上線」把改動送出去。

如果你不熟悉怎麼編輯這些檔案，**最簡單的方式是直接找 AI 協作**——見下方「情境四」。

---

## 情境二：我想在本機先預覽，確定改得沒問題再上線

如果你的電腦上有安裝 Node.js（一個讓電腦跑這類網站專案的工具）：

```bash
npm install     # 第一次使用前執行一次即可
npm run dev
```

接著在瀏覽器打開 `http://localhost:4321`，就能看到跟正式網站一樣的畫面，即時預覽你的修改。改完、看過沒問題後，再進行「情境三」發布。

---

## 情境三：怎麼發布上線

```bash
npm run build
```

這個指令會產生一個 `dist/` 資料夾，裡面是純粹的網頁檔案（HTML/CSS/圖片），把整個 `dist/` 資料夾上傳到網站空間，就完成更新了。

（實際部署方式——例如是否設定成「存檔就自動上線」，或是需要手動上傳——待正式決定託管方式後在此補上詳細步驟。）

---

## 情境四：不會寫程式，想請 AI（Claude）幫忙改網站

這是這個專案刻意設計成「對 AI 友善」的原因——因為內容都是單純好讀的文字檔案，AI 可以直接理解、修改，不需要你自己動手寫程式碼。

做法：
1. 開啟 Claude Code（或其他能操作檔案的 AI 工具），把它指向這個專案資料夾。
2. 用白話文描述你要的改動，例如：「幫我新增一則活動公告，標題是ＯＯＯ，時間是ＯＯ，地點在ＯＯ」或「幫我把『理監事會』頁面的名單換成最新名單」。
3. 請 AI 先在本機預覽（情境二）給你看過，確認沒問題。
4. 確認後請 AI 幫你發布上線（情境三）。

**小提醒**：正式上線前，一定要先看過預覽再確認，不要讓 AI 自己直接發布——這是避免打字打錯、內容還沒審過就上線的簡單防呆習慣。

---

## 情境五：要交接給下一位負責人了，該給他什麼？

1. 這整個專案資料夾（或是它在 GitHub 上的位置，見下方）。
2. 這份手冊。
3. 網站託管帳號的存取權限（例如網域註冊商、網頁空間服務的登入方式）——這些不會存在這個資料夾裡，需要另外用密碼管理工具或書面方式交接。
