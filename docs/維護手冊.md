# 台灣性諮商學會網站 維護手冊

這份手冊是寫給「不一定懂寫程式，但需要負責網站內容」的人看的——不管你是現任或未來的理事長、秘書處、幹部，或是被指派來維護網站的夥伴。

目標只有一個：**就算完全沒碰過這個網站，照著這份手冊，也能自己改內容、自己上線，或是找 AI（例如 Claude）幫你做。**

---

## 這個網站是怎麼運作的（白話版）

不懂技術也沒關係，先建立這個大概念就好：

1. 網站的內容（文字、活動公告等）都寫在一個個「文字檔案」裡，不是存在某個你要登入的後台系統。
2. 這些檔案存放在一個叫做 **Git 倉庫（repository）** 的資料夾裡，你可以把它想成「有自動記錄每一次修改歷史的資料夾」——誰、什麼時候、改了什麼，都查得到，改壞了也能退回去。
3. 想要「發布」網站更新時，把改好的檔案「打包」成純網頁檔案，丟到網路空間上，網站就更新了。

這代表：就算未來換人負責、換掉某個工具或某個網路平台，內容本身永遠都在，不會被鎖在某一家公司的系統裡打不開。這也是這次特地不選 Wix/Weebly 這類「一站式」平台的原因。

## 情境一：我只是要改文字／新增一則活動公告

（本節待網站頁面架構定案後補上實際操作步驟與範例檔案路徑）

大方向會是：
1. 找到對應的內容檔案（例如「課程公告」對應的檔案）。
2. 複製一份現有的活動格式，改成新的日期、標題、內容。
3. 存檔。
4. 依「情境三：怎麼發布上線」把改動送出去。

如果你不熟悉怎麼編輯這些檔案，**最簡單的方式是直接找 AI 協作**——見下方「情境四」。

### 想幫課程／年會加上海報圖

1. 把圖片檔放進 `public/images/courses/`（年會海報放 `public/images/annual/`）。
   檔名建議用「日期-課程簡稱」，例如 `2026-08-22-夜遊林森北路.jpg`，之後才找得到。
2. 在該筆活動資料裡加一行 `poster:`，路徑從 `/images/` 開始寫：

   ```
   poster: "/images/courses/2026-08-22-夜遊林森北路.jpg",
   ```

   活動資料各自放在：`src/pages/news/index.astro`（活動公告）、
   `src/data/course-reports.ts`（課程報導）、`src/data/annual-conferences.ts`（年會）。
3. 沒有海報的活動就不要寫這一行，版面會自動略過圖片區塊，不會破版。

圖片會自動縮放：卡片上顯示的是海報上半部（標題那一區），
點課程頁裡的大圖可以看原尺寸完整海報。
海報如果超過 1MB，先請 AI 幫忙壓縮再放進去，不然訪客載入會很慢。

### 想放一份可以下載的檔案（表格、法規全文）

1. 把檔案放進 `public/downloads/`，檔名用中文沒關係，但**不要有空格**。
2. 在頁面上用 `FileDownload` 元件掛出來，例如：

   ```
   <FileDownload
     href="/downloads/台灣性諮商學會-個人會員入會申請書.pdf"
     name="個人會員入會申請書"
     format="PDF"
     size="98 KB"
     note="111.10 版・適用專業／一般／學生會員"
   />
   ```

   `size` 請填實際大小（在終端機下 `ls -lh public/downloads/` 就看得到），
   讓訪客點之前就知道要下載多大的檔案。

**入會申請書之後要換新版時**：把新的 PDF 用同一個檔名蓋掉舊的，
再到 `src/pages/membership/index.astro` 最上面把 `applicationForm` 的
`size` 和 `version` 兩行改成新的就好，頁面其他地方不用動。

### 想換掉首頁那支介紹影片

首頁「認識性諮商」那一區嵌了一支 YouTube 影片。要換成別支的話，需要兩樣東西：

1. **影片 ID**：YouTube 網址 `youtube.com/watch?v=XXXXXXX` 裡 `v=` 後面那一串就是。
2. **封面圖**：把 `https://i.ytimg.com/vi/影片ID/maxresdefault.jpg` 在瀏覽器打開、另存圖片，放進 `public/images/video/` 資料夾。

然後打開 `src/pages/index.astro`，找到 `<VideoEmbed`，把 `videoId`、`title`、`poster`、`source`（影片來源頻道）這幾項換掉即可。

**為什麼要自己存封面圖？** 這樣訪客一進首頁不會馬上連到 YouTube。只有真的按下播放鍵，才會去跟 YouTube 拿影片——頁面載入比較快，沒看影片的訪客也不會被 YouTube 記錄。這是刻意的設計，換影片時請一併換掉封面圖，不要改成直接吃 YouTube 的網址。

**如果影片不是學會自己拍的**，`source` 一定要填原頻道名稱，會顯示在影片下方標明出處。

### 網站上的「歷史內容」放在哪

從舊 Weebly 站搬過來的舊資料，都放在 `src/data/` 底下，各管各的：

| 檔案 | 裝什麼 | 對應的網頁 |
| --- | --- | --- |
| `course-reports.ts` | 當年度的課後報導 | /news/reports |
| `course-reports-archive.ts` | 2020–2025 年的舊課後報導 | /news/reports |
| `lectures-archive.ts` | 2018–2025 年辦過的課程存檔＋海報 | /news/lectures |
| `annual-conferences.ts` | 歷屆年會的主題、講座內容、現場照片 | /annual |
| `chair-interviews.ts` | 歷屆理事長專訪（溯源計畫） | /about/history |
| `course-credits.ts` | 認證委員會審核過的課程，各自對應到哪一類認證時數 | /counselors/course-credits |

寫新的一篇課後報導時，加在 `course-reports.ts`（新的排最前面）就好，
舊的那份 `-archive` 檔案不用動；網站會自動把兩份合起來、依年份分組顯示。

### 想在「課程認證對照表」加一門新審核通過的課

`/counselors/course-credits` 這一頁，是給要申請性諮商師認證的會員對照用的：
他上過的某一門課，究竟算「人類性學 A 必修」的第幾項、可以認幾小時。
資料全部放在 `src/data/course-credits.ts` 的 `approvedCourses` 陣列裡。

認證委員會每審過一門新課，就在那個陣列的最後面照著前一筆的樣子加一筆：

```
  {
    title: "課程名稱",
    org: TASC,                     // 開課單位，荷光可寫 HG，兩家合開寫 `${TASC}、${HG}`
    instructor: "講師姓名",
    date: "2026/10/26",
    format: "視訊",                 // 實體／視訊／實體工作坊／實體走讀……照實寫
    totalHours: "2 小時",           // 課程總時數，不一定等於認證時數
    credits: [{ bucket: "B", topic: 5, hours: 2 }],
    status: "approved",
  },
```

`credits` 就是這門課被認到哪些類別：`bucket` 填 `A`（人類性學必修）、
`B`（人類性學選修）、`T`（性諮商訓練）或 `S`（性態度訓練）；`topic` 填該類別
底下的領域編號（`S` 類沒有編號，填 `null`）；一門長時數的培訓課可以同時列好幾筆。
如果審核時有但書（例如時數待確認），多加一行 `note: "……"`，並把 `status`
改成 `"note"`；如果還沒審完就填 `"pending"`。存檔後頁面上的對照表、
反查清單、筆數統計都會自己更新，不用改別的地方。

**這份資料裡不要放申請人姓名、email、電話，也不要放委員的名字。**
原始的審核表單有這些欄位，但網站上是公開頁面，只放跟課程認定有關的內容。

### 網站上那些彩色的圓圈和小人是什麼？

那不是圖片檔，是用程式畫出來的向量圖形，全部從學會的 logo 延伸出來，
所以放到多大都不會糊，換色也只要改一個地方。它們都放在
`src/components/decor/`，一共三個：

| 檔案 | 長什麼樣 | 現在用在哪 |
| --- | --- | --- |
| `FigureRing.astro` | logo 上那三個人圍成的環（紅／藍／黃） | 首頁大標右邊、每個內頁的標題區、文章標題區、待補內容的說明框 |
| `FigureMark.astro` | 單獨一個小人 | 首頁四張使命卡的底紋、聯絡我們的寄信卡 |
| `ArcField.astro` | 一圈圈細細的弧線 | 首頁「最新消息」區塊的背景 |

三人環的角度是從 `public/logo.png` 的像素量出來的，跟真正的 logo 對得上；
**真正代表學會的標誌還是 `logo.png`**（用在導覽列和頁尾），這些只是裝飾。

想在某個地方加裝飾，最省事的講法是直接跟 AI 說：
「這一頁的某某區塊右邊太空了，幫我用 `src/components/decor/` 裡的元件補一下。」

## 情境二：我想在本機先預覽，確定改得沒問題再上線

如果你的電腦上有安裝 Node.js（一個讓電腦跑這類網站專案的工具，通常請 AI 協助安裝一次即可）：

1. 打開「終端機」（Terminal，Mac 內建的黑底程式，在 Spotlight 搜尋「終端機」就找得到）。
2. 輸入以下指令，把「路徑」換成這個專案實際存放的位置（目前是 `/Users/dr.lin/Desktop/tasc-website`），按 Enter：
   ```bash
   cd /Users/dr.lin/Desktop/tasc-website
   npm run dev
   ```
3. 畫面會顯示一行類似 `Dev server running at http://localhost:4321`（也可能是別的數字，例如 4400——如果 4321 已經被其他專案占用，系統會自動換一個空的）的訊息。**那個網址就是你要打開的預覽網址**。
4. 打開瀏覽器（Safari／Chrome 都可以），貼上那個網址（例如 `http://localhost:4400`），就能看到跟正式網站一樣的即時預覽，改檔案存檔後畫面會自動更新，不用重新整理。

**重要提醒**：這個預覽只有「終端機那個視窗還開著、程式還在跑」的時候才看得到——關掉終端機視窗，或請 AI 結束這個指令，網址就會打不開（顯示「無法連上這個網站」）。如果你發現預覽網址突然打不開了，代表程式被停掉了，只要重新執行一次上面的 `npm run dev` 就能再打開。之後如果想直接跟 AI 說「幫我把預覽打開」，AI 就會重新啟動並告訴你網址。

改完、看過沒問題後，再進行「情境三」發布上線（正式讓所有訪客都看得到）。

## 情境三：怎麼發布上線

**現在是自動的，你不用做打包、也不用上傳檔案。**（2026-08-18 設定完成）

流程長這樣：

```
你電腦上的專案  →（git push 送出去）→  GitHub  →（Netlify 自己打包）→  網站更新
```

- 程式碼放在 GitHub 的私人儲存庫：`ntnuchinese1024-code/tasc-website`
- 網站由 Netlify 託管，目前網址是 <https://tasc-preview.netlify.app>（理監事審閱用的預覽站，頁面上方有「預覽版」橫幅）
- 只要有新的改動被送上 GitHub 的 `main` 分支，Netlify 就會自己跑 `npm run build`、自己把結果放上網，大約一分鐘後網址就是新的。打包指令跟輸出資料夾寫在專案根目錄的 `netlify.toml`，不用去 Netlify 後台設定。

實際操作只有一行（請 AI 幫你做也可以）：

```bash
git push
```

**要確認有沒有成功**：到 <https://app.netlify.com> 打開 tasc-preview 專案，看 **Deploys** 那一頁。綠色的 Published 就是好了；紅色的 Failed 表示打包出錯（通常是檔案裡有打錯字），點進去可以看錯誤訊息，把訊息貼給 AI 就能修。

### 幾個要注意的地方

- **送出去 = 上線**，中間沒有人工確認那一關。所以請 AI 幫忙改東西時，維持這個習慣：**先在本機預覽（情境二）看過，確認沒問題，才叫 AI 送出去。**
- **不要用 Netlify 後台那個「Work with an AI agent」的功能改網站。** 它改的是 Netlify 上的檔案，不是你電腦裡的專案，兩邊會各走各的，之後就分不清哪一份才是正確版本。
- **不要再用「拖曳資料夾上傳」的方式發布**（Netlify 首頁那個 Drag and drop 的框）。手動上傳會蓋掉自動部署的結果，網站就會停在那份手動的快照、之後改什麼都看不到——這個網站在 2026-08-18 之前就是卡在這個狀況。
- 之後如果申請了正式網域，在 Netlify 的 **Domain management** 裡設定，程式碼這邊不用改。

## 情境四：不會寫程式，想請 AI（Claude）幫忙改網站

這是這個專案刻意設計成「對 AI 友善」的原因——因為內容都是單純好讀的文字檔案，AI 可以直接理解、修改，不需要你自己動手寫程式碼。

做法：
1. 開啟 Claude Code（或其他能操作檔案的 AI 工具），把它指向這個專案資料夾。
2. 用白話文描述你要的改動，例如：「幫我新增一則活動公告，標題是ＯＯＯ，時間是ＯＯ，地點在ＯＯ」或「幫我把『理監事會』頁面的名單換成最新名單」。
3. 請 AI 先在本機預覽（情境二）給你看過，確認沒問題。
4. 確認後請 AI 幫你發布上線（情境三）。

**小提醒**：正式上線前，一定要先看過預覽再確認，不要讓 AI 自己直接發布——這是避免打字打錯、內容還沒審過就上線的簡單防呆習慣。

## 情境五：要交接給下一位負責人了，該給他什麼？

1. 這整個專案資料夾（或是它在 GitHub 上的位置，見下方）。
2. 這份手冊。
3. 網站託管帳號的存取權限（例如網域註冊商、網頁空間服務的登入方式）——這些不會存在這個資料夾裡，需要另外用密碼管理工具或書面方式交接。
