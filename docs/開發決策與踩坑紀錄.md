# 開發決策與踩坑紀錄

給接手的維護者（和協作的 AI）看：哪些事是**刻意這樣做**的、哪些坑已經踩過。
改動之前先看一下，避免把刻意的設計「順手修掉」，或重踩同一個坑。
（2026-11 從原開發者的個人 AI 記憶整理進 repo，之後新的決策請直接補在這份文件。）

> 這個 repo 是公開的。這份文件、以及 repo 裡任何檔案，都不能寫入金鑰、deploy hook 網址、個人聯絡資料。

## 專案定位

- 2026-08-15 起取代到期的 Weebly 舊站（`tasctaiwan.weebly.com`），舊站內容備份在 `archive/weebly-content/`。
- **完全獨立於 `sexpsy-website`**：不共用 repo、元件、樣式、內容。若有人想共用，先確認是否真的要打破這個隔離。
- Astro 純靜態站，輸出的 `dist/` 丟到任何空間都能跑，「不綁平台、隨時可搬遷」是核心原則。
- 未來維護者不一定有工程背景，預期是「新負責人＋AI」。所以內容檔要乾淨好懂，不做花俏的 CMS 後台。操作說明在 `docs/維護手冊.md`。
- 課程、報導由報名系統（`tasc-registration`，Supabase）供稿，官網**在建置時**抓 `/api/events` 生成靜態頁（為了讓 Google 收錄）。抓不到資料只會印警告、回空陣列，絕不讓官網建置失敗。即時名額另外由瀏覽器 fetch `/api/events/<slug>/status` 補正。
- 刻意留在本地檔案、不搬進資料庫的：歷年年會（`src/data/annual-conferences.ts`，結構太細、不會再變動）、歷年講座（`src/data/lectures-archive.ts`，只有簡介沒有內文）。原則：會反覆變動、需要收報名的走資料庫；凍結的歷史存檔留在這個 repo。
- 本地舊報導與資料庫報導合併成同一形狀，**同 slug 以資料庫為準**。

## 部署

- **Cloudflare Worker（靜態資源）`tasctaiwan`**，接 GitHub `main` 自動部署：Build `npm run build`、Deploy `npx wrangler deploy`。
- repo 必須有 `wrangler.jsonc`（`name` 要跟 Worker 同名、`assets.directory: ./dist`）和 `.node-version`（Astro 7 需要 >= 22.12）。
- 為什麼不是 Netlify：2026-08-21 Netlify 帳號被誤鎖（顯示額度用完，實際用量為 0），等不了一個月就搬走了，`netlify.toml` 已刪除。為什麼是 Worker 而不是 Pages：Pages 的「直接上傳」專案無法改接 Git，也就沒有 deploy hook。
- 報名系統後台發布時會打 Cloudflare Workers Builds 的 deploy hook（網址存在 Vercel 的 `SITE_DEPLOY_HOOK_URL`）。
- `.github/workflows/daily-rebuild.yml` 每天台北 00:30 重建，讓過期課程自動移到「已結束」。hook 存在 GitHub repository secret `DEPLOY_HOOK_URL`。注意：repo 連續 60 天沒有 commit，GitHub 會自動停用排程。
- 網域 `tasctaiwan.tw` 在 Gandi 購買，DNS 在 Cloudflare。主網址 `www.tasctaiwan.tw`（`astro.config.mjs` 的 `site`）。
- **從 Worker 移除自訂網域會連 DNS 記錄一起刪掉**，整站斷線，而且各地 DNS 會把「查無此網域」快取一段時間。換網域要先加到新專案、再從舊的移除。加網域要選 Custom domain，不要選 Route。
- Cloudflare 預設會在 `robots.txt` 前面注入一段內容，擋掉 AI 爬蟲。學會希望**開放** AI 收錄，要在後台 AI Crawl Control 關掉。
- `tasc-preview.netlify.app` 是廢棄的舊預覽站，驗證一律打 `tasctaiwan.tw`。

## Git 與協作

- **commit 訊息不要加 `Co-Authored-By`**。當年 Netlify 免費方案會把 co-author 算成第二位貢獻者，導致建置失敗；搬到 Cloudflare 後沿用這個慣例。作者統一用 `Drlin <ntnuchinese1024@gmail.com>`。
- **push 到 `main` = 上線**。改完先 commit 在本機或推到別的分支，等維護者本機預覽確認後才推 `main`。
- 這個 repo 曾經有好幾個 AI 工作階段同時在改。**不要用 `git add -A`**：先 `git status` 看有沒有不是自己改的檔案，再逐一 `git add <檔案>`。工作中途也要再看一次。
- 本機 dev server 用 port 4400。
- 跟維護者溝通時，git／部署術語（push、merge、branch、hook…）要先用白話講清楚「這是什麼、做了會怎樣」，再請對方決定。

## 視覺與排版（維護者明確要求過的）

- **正式色碼**定義在 `src/styles/global.css`，是從 logo 原檔像素取樣的：紅 `#E73828`、藍 `#009FE8`、黃 `#FFF000`、綠 `#1EAB39`，輔助色橙 `#EB5613`、洋紅 `#E71374`。原色多數不符合無障礙對比，所以每個顏色都有一個 `-deep` 版本給文字和按鈕用，原色只用在裝飾。
- 底色是石灰白 `#F2EFE7`。偏 peach 的暖米色被否決過：在性諮商的語境下容易讓人聯想到膚色。
- **字型用系統字型**（Noto Serif TC／Noto Sans TC），不要嵌入自訂字型。霞鶩文楷、Chiron Sung HK 都試過，都因為字符子集沒收全而缺字。
- **中文標題不能有一字成行**：`src/lib/wrap-heading.ts` 依標點切子句並鎖住不換行，超過 16 字的子句只鎖最後兩字。手機版標題字級下限壓在 1.25rem 左右，否則長子句會被裁切。
- logo 環上是**三個**人形（不是四個）。裝飾元件在 `src/components/decor/`（`FigureRing`、`FigureMark`、`ArcField`）。
- **被否決的設計：把人形排成一長條重複的橫帶**（原話是「很醜」），不要再提案。單獨或少量的人形（聯絡頁三個人形、首頁使命卡的淡底紋）是保留的。
- `/news` 的 `.event-grid` 三欄寬度不完全相等是**刻意的**。改成 `minmax(0, 1fr)` 會讓長標題溢出，不要「順手修好」。
- 卡片本身是 `<a>` 時，`CoursePoster` 一定要傳 `linkToFull={false}`，否則會變成不合法的巢狀連結。
- 圖片一律轉成漸進式 JPEG、寬度上限約 1000–1100px，放在 `public/images/{courses,annual,lectures,chairs}/`，檔名用「日期-簡稱」。

## 性諮商師名單的地圖與搜尋（2026-11）

- 資料流程：`/counselors/profile` 表單 → 報名系統 `POST /api/counselor-profiles`（待審核）→ 秘書處在後台 `/admin/counselors` 通過 → 官網重建 → `/counselors` 建置時抓 `GET /api/counselor-profiles`。卡片都在建置時產生（Google 讀得到），篩選只是瀏覽器端切換顯示。
- 抓不到資料（報名系統還沒跑 018 migration 或連不上）時回空陣列，頁面顯示「建置中」，合格名單照常顯示。
- 「立體」地圖不用 3D 函式庫：SVG 裡把島的外框往下疊 12 層當厚度，再用 CSS `rotateX` 往後傾斜。金門、馬祖用左上角小框（照比例放會讓本島縮到看不清楚）。
- 地圖顏色與數字跟著「關鍵字＋專長」重算（不含地區），所以選了專長就看得到哪些縣市有這方面的性諮商師。篩選條件寫進網址（`?region=&specialty=&q=`），可以直接分享。
- 專長範本整理自 DSM-5／ICD-11 性健康分類、AASECT 認證性治療師常見服務項目，依台灣用語改寫、去病理化。範本只在官網，報名系統收自由字串，增減範本不用動後台。
- 工作地區代碼要三處一致：`src/data/counselor-directory.ts`、報名系統 `lib/types/counselor-profile.ts`、報名系統 018 migration 的 `counselor_region_codes()`。
- 地圖資料：`taiwan-atlas`（MIT，源自內政部村里界圖），用 `scripts/build-taiwan-map.mjs` 簡化成約 40KB 的 `src/data/taiwan-map.json`。

## 內容原則

- **不編造**：舊站沒寫的任期、課程名稱、時數，一律留空或標「待確認」，不自己推算。
- 課程認證對照表（`/counselors/course-credits`）已去識別化：不放申請人資料，也不放委員姓名，委員意見只摘錄與課程認定有關的部分。
- 年會、工作坊照片裡有學員正面入鏡的（舊站本來就公開），學會要求撤除時就撤除。
- 性諮商師合格名單標示「2024 年 9 月更新」，有新名單要跟理監事會確認後再換。
